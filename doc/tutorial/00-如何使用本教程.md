# 00 · 如何使用本教程

## 本章目标

读完之后你应该能回答：

- `src/` 里现在是空的还是满的？我该改哪里？
- 我怎么知道某一章做完了？
- 「手抄」的适用范围到底有多大？全部 5000 行都抄吗？
- 出错了怎么快速定位？

---

## 先说清楚这个项目**不是**什么

它**不是**一个能复现 GPT-2 的项目。硬件差了约 1250 倍 FLOPs，做不到。

它**也不是**一个把 nanochat 拆开讲讲的注释版。nanochat 的优化器有 3 个变体、
5 个残差流 trick、ZeRO-2 手写通信，一次性全塞给你只会让你迷路。

它**是**一个把 nanochat 的每个设计**单独拆出来、单独验证**的教学项目。
每一个设计你都会亲手打开、关掉、看数字。

## 最重要的一件事：`src/` 里现在是**骨架**

```
$ grep -A3 "^def attend" src/model/layers.py
def attend(q, k, v, window):
    """
    训练时的注意力。
    ...
    """
    raise NotImplementedError(
        "待实现：attend —— 见 docstring 的三步
          1) 算 gqa = (q.size(2) != k.size(2))
          2) 如果窗口是全上下文 -> sdpa_bt(q,k,v, causal=True, gqa=gqa)
          3) 否则构造 mask：...
        验证：uv run pytest -k attend -v")
```

每个要实现的地方都长这样：**一句「要做哪几步」+ 一个「怎么验证」**。
你把函数体填上，pytest 就绿了。

**这不是建议，是硬约束** —— 每个函数都有测试守着，只读代码过不了。

## 「手抄」的适用范围是有原则的

我一开始把整个教程都标成「推荐手抄」，那是错的。5000 行代码抄一遍
20-25 小时，抄完之后你记住的是**肌肉记忆**，不是理解。

真正的判据是：**抄的时候你需不需要做决策？**

| | 需要决策？ | 例子 |
|---|---|---|
| best-fit 装箱 | **要** | 为什么先选最长的？为什么裁最短的？ |
| QK-Norm | **要** | 放在哪一步？缩放系数怎么定？ |
| Newton-Schulz | **要** | 高矩阵和宽矩阵的迭代形式不同，为什么？ |
| 日志格式化 | 不用 | `f"step {n}"` 里没有什么要想的 |
| 存档逻辑 | 不用 | 「.tmp + rename 保证原子性」是知道就行 |

所以：

| 范围 | 手抄 | 理由 |
|---|---|---|
| 卷 1 数据（680 行） | 手抄 | best-fit 装箱是全项目最有价值的一段，值得亲手写出来 |
| 卷 2-3 模型（810 行） | 手抄 | 组件小、边界清晰，逐个敲能建立对 shape 的手感 |
| 卷 4 优化器（630 行） | 手抄 | `orthogonalize_simple` 那 20 行必须懂 SVD 才写得出来 |
| 卷 5 训练循环（1500 行） | **只读** | 纯工程（日志、存档、调度循环），抄一遍不产生理解 |
| 卷 6-8 分布式/对齐/收尾 | **只读** | 同上 |

**手抄总量约 2100 行，8-11 小时。** 这是一个能完成、且完成时有收获的量。

## 教程里的代码块是折叠的

每一章的「手抄代码」小节里，参考答案包在 `<details>` 里，
标题是「👀 展开参考答案（先自己想 20 分钟）」。

**为什么要折叠而不是不给？**
因为有些地方（比如第 03 章的玩具 BPE）你可能想先看看整体形状再动手。
折叠提供了「先自己想」和「实在想不出来」之间的缓冲，而不是硬切成两断。

**建议**：卡住超过 20 分钟再看。看完之后关掉答案**重新写一遍** ——
「看懂了」和「写得出」之间差着整个理解。

## 两条路线

### 路线 A：跟敲（推荐，8-11 小时 + 4-8 小时消融）

照着 `raise` 消息和教程的「概念」部分自己实现，跑通判据再继续下一章。

好处：你会记住那些「不这么做就会 nan / 会泄漏未来 / 会静默算错」的坑。
本项目里的每一个坑都是真踩过的，骨架的注释里都标了「曾经的 bug」。

坏处：慢，而且中途会有很多次「数字不对」的挫败。

### 路线 B：通读（3-4 小时）

```bash
git checkout solution      # 完整实现
```

本教程当注释读，重点看每章的「概念」和「延伸」两节。
看完 `git checkout main` 回来。

好处：快速建立全貌，知道每个零件叫什么、为什么存在。
坏处：坑还是会踩，只是知道坑名叫什么。

### 混合（我最推荐的）

**卷 1-4 跟敲**（数据、模型、trick、优化器 —— 理解 GPT 的核心），
**卷 5-8 通读**（训练循环、分布式、对齐 —— 更像工程而非原理）。

## 四档规模怎么选

```bash
bash script/train_base.sh debug   # 秒级。写代码时用这个，改一行就重跑
bash script/train_base.sh smoke   # 2-3 分钟。每章的「动手验证」用这个
bash script/train_base.sh ablation  # d6，约 44 分钟。做消融实验用这个（信号更干净）
bash script/train_base.sh full      # d24，约 41 小时。消融后的最佳组合，只训一次
```

**关键**：消融实验必须用 `ablation` 档。`smoke` 档只有 896 步、14M token，
val bpb 的随机波动（约 ±0.02）和你要测的效应（0.01-0.09）同量级。

`debug` 档（20 步）**完全测不出架构差异** —— 实测五组变体的 bpb
全部是 3.2564，模型还在初始化附近。

## 出错了怎么定位

**第一步永远是跑测试**：

```bash
uv run pytest tests/ -v
```

194 个测试：卷0 15 + 卷1 31（21 + 精确续训 10）+ 卷2-3 28 + 卷4 14 + 只读护栏 106
+ 只读代码护栏 103（metrics 11 + checkpoint 15 + engine 50 + tasks 27）
另有 10 个判据自检（`tests/test_judging_soundness.py`），
全量 `pytest tests/` 收集到 192 个。
专门覆盖「看起来对其实错了」的 bug。几个重点：

| 测试名 | 锁住的坑 |
|---|---|
| `test_sdpa_layout_is_bhtd_not_bthd` | PyTorch SDPA 严格按 `(B,H,L,E)` 解读，`T==1` 时**形状对但数值错** |
| `test_causality_no_future_leak` | attention 的 causal mask 漏了（最严重的 bug） |
| `test_rope_relative_position` | RoPE 的相对位置性质 |
| `test_every_row_starts_with_bos` | 手动 `row[0]=bos` 加上文档自带的 BOS |
| `test_truncate_left_keeps_supervision` | SFT 截断把监督信号全切掉 → NaN |
| `test_muon_plus_rescues_low_rank` | Newton-Schulz 推不动近零奇异值 |
| `test_forward_loss_starts_uniform` | 初始 loss 应该约等于 `ln(vocab_size)` |
| `test_param_grouping_covers_all_params` | 漏掉参数（症状隐蔽：训练正常但某模块一直是随机初始化） |

**loss 变成 `nan` 的三个常见原因**：

1. 某个张量没被正确初始化 —— 检查是不是在 meta device 上创建了却没在
   `init_weights` 里重算（卷3 第 16 章，这是我真踩过的）
2. 整批 `targets` 都是 `-1` —— `F.cross_entropy` 算 0/0（卷1 第 04 章，
   SFT 里 23% 的样本会踩中）
3. 某个除法/范数分母为 0

**第三步**：`debug` 档 + 在关键位置打印张量的 `dtype` / `shape` / `abs().max()`。
那些十六进制内存地址式的报错信息基本都和 dtype 或 shape 有关。

## 一个建议：不要跳过消融实验

如果你只读概念不跑消融，最后你会得到一堆「听起来很有道理」的知识，
但说不出 RoPE 到底值多少 bpb、Muon 比 AdamW 好多少、滑窗在 SDPA 上慢多少倍。

消融实验是这个教程唯一能给你的东西。全部做完你会得到一张表，
长这样（下面是 smoke 档实测的真实数字）：

| 变体 | val_bpb | 差值 | 解读 |
|---|---|---|---|
| 基线（RoPE + QK-Norm + ReLU²） | 1.7136 | — | |
| **去掉 RoPE** | 1.8013 | **+0.0877** | 最大的单项影响。序列 512 已经开始依赖位置信息 |
| **GELU 替代 ReLU²** | 1.7240 | **+0.0104** | relu² 确实略好，印证 nanochat 的说法 |
| 去掉 QK Norm | 1.7098 | −0.0038 | **噪声**（绝对值小于 0.02，要重跑确认） |
| 用 PAD 代替 best-fit | 待测 | — | 卷1 的核心消融 |
| Muon simple 转 advanced | 待测 | — | 卷4 的核心消融 |

这张表是**你**的，不是 nanochat README 上的。这才是这个项目存在的意义。

> ⚠ 这张表里的数字来自 **smoke 档**（d4 / 896 步 / 2-3 分钟），
> 不是 ablation 档。它们足以看出 RoPE、ReLU² 这种**大效应**
> （Δ 0.01 ~ 0.09），但 QK-Norm 那一行（Δ −0.0038）落在噪声范围内，
> 不能下结论。
>
> **要得出可信结论必须用 `ablation` 档**（d6 / 3096 步 / 约 44 分钟）：
> smoke 档的 bpb 噪声（±0.02）大于大部分单项效应本身。
> 下面是 smoke 档的复现命令（快，适合先跑通流程）：

**复现方法（smoke 档，2-3 分钟/次）**：

```bash
uv run python -m training.train_base --mode smoke --no-resume --model-tag d4base
uv run python -m training.train_base --mode smoke --no-resume --model-tag d4norope --no-rope
bash scratch/ablation.sh d4base
```

**升级到 ablation 档**（可信结论）：

```bash
uv run python -m training.train_base --mode ablation --no-resume --model-tag d6_base
uv run python -m training.train_base --mode ablation --no-resume --model-tag d6_norope --no-rope
bash scratch/ablation.sh d6_base
```

**三个必须注意的坑**（我踩过）：

1. **不加 `--no-resume` 会得到全等的 bpb。**
   auto-resume 会把上次同名 tag 的存档捡起来，0 步就跑完了 ——
   两组数字一模一样，看起来像「这个 trick 毫无影响」，其实根本没训练。

2. **`debug` 档测不出架构差异。**
   实测五组变体 bpb 全部是 3.2564（20 步，模型还在初始化附近）。

3. **`|Δ| < 0.02` 时重跑一次。**
   那个量级是初始化随机性的波动范围，不是真实效应。
