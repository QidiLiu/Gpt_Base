## 概念：五步和它们的形状

```
输入 x: (B, T, D)                    D = n_embd

(1) 投影      c_q: D→H·Dh    q (B,T,H,Dh)
             c_k: D→Hkv·Dh  k (B,T,Hkv,Dh)
             c_v: D→Hkv·Dh  v (B,T,Hkv,Dh)

(2) RoPE      apply_rotary_emb(q, cos, sin)   ← 只对 q,k
             apply_rotary_emb(k, cos, sin)

(3) QK-Norm   q = rms_norm(q) * 1.2
             k = rms_norm(k) * 1.2

(4) 加权      attend(q,k,v,window)   →  (B,T,H,Dh)
             （内部转成 (B,H,T,Dh) 给 SDPA，转回来）

(5) 输出投影  y.view(B,T,H·Dh) = (B,T,D)
             c_proj: D→D       →  (B,T,D)
```

`full` 档的具体数字：`D=768, H=12, Dh=64, Hkv=12`（无 GQA）。
所以 `c_q: 768→768`、`c_k: 768→768`、`c_v: 768→768`，
`c_proj: 768→768`。四个矩阵各 590K 参数，一个注意力块共 2.36M。

## 概念：为什么全程用 `(B, T, H, D)`

SDPA（`F.scaled_dot_product_attention`）的签名是 `(B, H, L, E)`。
而 nanochat 全程用 `(B, T, H, D)`。为什么不按 SDPA 的习惯来？

理由是**取 head 的成本**：

```
(B,T,H,D)  →  view(B,T,H,D) 一步到位（本来就是这个布局）
(B,H,T,D)  →  先在投影处 transpose 成 (B,H,T,D)，用完再转回 (B,T,H,D)
```

而 SDPA 接受「任意前两维是 batch 的 4D 输入」，所以 `(B,T,H,D)`
直接喂给它就行 —— 只需要在 `sdpa_bt` 里做两次 transpose（见第 11 章，
实测开销约 0.06ms，可忽略）。

**净结果**：省掉 24 个 Block × 4 次 transpose，换来两次。

---

## 概念：因果性从哪来

`attend()` 的核心是 `is_causal=True`：

```
logits[i][j] = q_i · k_j / √d       j > i 的位置被设为 -inf
```

softmax 之后 `-inf` 位置的权重是 0，所以位置 `i` 只能看到
`j ≤ i`。这就是「causal」的机制 —— **一个 mask 就够了**。

本项目默认 `window_pattern = "L"`（全上下文），所以走的是
`is_causal=True` 这条最快路径（SDPA 的 flash kernel）。
滑窗路径见第 20 章。

---

## 概念：QK-Norm 在防什么

不加 QK-Norm 时，`logits = q · k / √d` 的量级不受控。
训练早期权重随机，可能出现 `|logits| > 50` 的情况：

```
softmax([50, -50, ...]) ≈ one-hot
```

此时 softmax 的梯度 `p - y` 几乎全在正确位置上，其余为 0 ——
**梯度消失**，而且这种状态一旦形成就很难恢复。

QK-Norm 的做法：

```python
q = rms_norm(q) * self.qk_norm_scale   # 1.2
k = rms_norm(k) * self.qk_norm_scale
```

`rms_norm` 把 q/k 拉回「RMS = 1」（即 `|q| = √Dh`），再乘系数 1.2。
由 Cauchy-Schwarz 不等式：

```
|q| = |k| = 1.2 × √64 = 9.6
|q · k| ≤ |q| × |k|          = 92.16
|logits| = |q · k| / √64     = 11.52   ← 上界
```

**这个上界与输入的绝对量级完全无关** —— 无论权重长成什么样，
logits 都不可能超过 11.52，永远进不了饱和区。
（实测那次是 5.37，落在上界之内。）

**代价**：每个 head 只能表达「方向」，不能表达「强度」。
因为归一化之后所有 q/k 的长度都相同了，「这个 key 很重要」
这种信息无法通过内积大小表达。

> `qk_norm_scale = 0.0` 就是关掉它。这是第 12 章的消融开关。

---

## 概念：四 个投影矩阵 vs 一个融合矩阵

nanoGPT 用一个融合的 `c_attn: D → 3D`（一次算 q/k/v）。
本项目拆成 `c_q` / `c_k` / `c_v` / `c_proj` 四个。理由：

1. **Muon 要求同组参数形状相同**（第 27 章）。融合矩阵是
   `(D, 3D)` 的一个 2D 张量，而拆分后 `c_q`/`c_k`/`c_v`/`c_proj`
   都是 `(D, D)` —— 形状一致，能被 Muon 一起堆叠处理。
2. **QK-Norm 只该作用于 q/k**，融合矩阵出来还要再切开才能分别
   归一化。拆开就没这个问题。

代价是四次小矩阵乘而不是一次 —— 但 GEMM 的效率对小矩阵不敏感，
实测没有可测差异。

## 手抄代码

### 第 1 块：`attend` 的分派

```python
def attend(q, k, v, window, attn_impl="flex"):
    """
    left = window[0]  (left, right) 元组，(T,0)=全上下文 (W,0)=滑窗
    """
    left = window[0]
    T = q.size(1)
    if left is None or left <= 0 or left >= T:
        # 全上下文：最快路径，本来就是 FA2
        return sdpa_bt(q, k, v, causal=True, gqa=(q.size(2) != k.size(2)))
    if attn_impl == "flex":
        return attend_sliding_flex(q, k, v, left)
    return attend_sliding_sdpa(q, k, v, left)
```

⚠ `attend` 和 `attend_sliding_flex` / `attend_sliding_sdpa`
（第 11、20 章会讲后面两个）已经写好了 —— 本章只写**分派逻辑**。

### 第 2 块：`CausalSelfAttention.__init__`

```python
def __init__(self, cfg, layer_idx: int, device=None):
    super().__init__()
    self.layer_idx = layer_idx
    self.n_head = cfg.n_head
    self.n_kv_head = cfg.n_kv_head
    self.head_dim = cfg.head_dim
    self.d_model = cfg.n_embd
    self.qk_norm_scale = cfg.qk_norm_scale
    self.use_rope = cfg.use_rope
    self.attn_impl = getattr(cfg, "attn_impl", "flex")

    assert cfg.n_head % cfg.n_kv_head == 0, "n_head 必须是 n_kv_head 的整数倍"
    kv_dim = cfg.n_kv_head * cfg.head_dim

    self.c_q = Linear(self.d_model, self.n_head   * self.head_dim, bias=cfg.use_bias, device=device)
    self.c_k = Linear(self.d_model, kv_dim, bias=cfg.use_bias, device=device)
    self.c_v = Linear(self.d_model, kv_dim, bias=cfg.use_bias, device=device)
    self.c_proj = Linear(self.d_model, self.d_model, bias=cfg.use_bias, device=device)

    # Value Embedding 的门控（第 18 章）：每层一个 Linear，输出 n_kv_head 个标量
    self.ve_gate_channels = 12
    self.ve_gate = (Linear(self.ve_gate_channels, cfg.n_kv_head, bias=False, device=device)
                    if (cfg.use_value_embeds and has_value_embed(layer_idx, cfg.n_layer))
                    else None)
```

**本项目默认 `n_kv_head == n_head`（无 GQA）**。所以
`kv_dim == d_model`，四个矩阵形状完全一样（`(D, D)`）。

> 为什么 `assert cfg.n_head % cfg.n_kv_head == 0` 而不是
> `==`？因为 GQA 要求 n_head 是 n_kv_head 的整数倍才能分组共享 kv。
> 本项目默认关闭 GQA，但接口留着。

### 第 3 块：`CausalSelfAttention.forward`

```python
def forward(self, x, cos_sin, window, kv_cache=None, ve=None):
    B, T, _ = x.shape

    # (1) 投影 -> (B, T, H, Dh)。三个 view 都在最后一维拆分
    q = self.c_q(x).view(B, T, self.n_head,   self.head_dim)
    k = self.c_k(x).view(B, T, self.n_kv_head, self.head_dim)
    v = self.c_v(x).view(B, T, self.n_kv_head, self.head_dim)

    # Value Embedding 门控（第 18 章，这里只留 hook）
    if ve is not None:
        ve = ve.view(B, T, self.n_kv_head, self.head_dim)
        gate = 3 * torch.sigmoid(self.ve_gate(x[..., :self.ve_gate_channels]))
        v = v + gate.unsqueeze(-1) * ve

    # (2) RoPE：只对 q,k，不对 v
    cos, sin = cos_sin
    if self.use_rope and cos.size(1) >= T:
        q, k = apply_rotary_emb(q, cos, sin), apply_rotary_emb(k, cos, sin)

    # (3) QK-Norm：先归一化，再乘可学系数
    if self.qk_norm_scale > 0:
        q = rms_norm(q) * self.qk_norm_scale
        k = rms_norm(k) * self.qk_norm_scale

    # (4) 加权 + KV cache 推进（第 34 章）
    if kv_cache is None:
        y = attend(q, k, v, window, attn_impl=self.attn_impl)
    else:
        kc, vc = kv_cache.get_layer(self.layer_idx)
        y = attend_with_kvcache(q, kc, vc, k, v, kv_cache, window,
                                attn_impl=self.attn_impl)
        if self.layer_idx == kv_cache.n_layers - 1:
            kv_cache.advance(T)

    # (5) 合并头 + 输出投影
    y = y.contiguous().view(B, T, self.d_model)
    return self.c_proj(y)
```

⚠ **`.contiguous()` 不是可选的。** `view` 要求张量内存连续，
而 `attend` 内部经过两次 transpose，返回的是非连续的视图。
漏掉 `.contiguous()` 会报 `view size is not compatible`，
但报错信息不会告诉你真正原因是上一步的 transpose。

uv run pytest tests/test_core.py -k attend -v

关键判据是 `test_attend_matches_manual_reference`：

```python
# 完全按教科书公式手写一遍
qt, kt, vt = (x.transpose(1, 2) for x in (q, k, v))
logits = (qt @ kt.transpose(-2, -1)) / D ** 0.5
mask = torch.tril(torch.ones(T, T, dtype=torch.bool))
logits = logits.masked_fill(~mask, float("-inf")).softmax(-1)
ref = (logits @ vt).transpose(1, 2)
assert torch.allclose(got, ref, atol=1e-5)
```

**这个判据的价值**：它是「实现是否忠于公式」的独立检验 ——
不依赖 `sdpa_bt` 的正确性。如果 SDPA 的布局参数搞反了

### 验证 3：QK-Norm 确实限制了 logits 范围

```python
import sys, torch
sys.path.insert(0, "src")
from model.layers import rms_norm

Dh = 64
for scale, name in ((None, "不加 QK-Norm"), (1.2, "加 QK-Norm")):
    torch.manual_seed(1)
    q = torch.randn(4096, Dh) * 5      # 人为放大 5 倍
    k = torch.randn(4096, Dh) * 5
    if scale is not None:
        q = rms_norm(q) * scale
        k = rms_norm(k) * scale
    logits = (q * k).sum(-1) / Dh ** 0.5
    p = logits.softmax(-1)
    print(f"{name}: |logits|max={logits.abs().max():8.2f}  "
          f"softmax 最大值={p.max():.6f}")
```

实测：

```
不加 QK-Norm     |logits|max=  96.53  softmax max=0.593724
加 QK-Norm        |logits|max=   5.37  softmax max=0.014096
```

**logits 上界从 96.5 压到 5.4（18×），softmax 最大值从 0.59 压到
0.014（42×）。**

注意这里 softmax 还没到 1.0 —— 因为只有 4096 个候选，且它们之间
差距有限。真正危险的情形是 logits 达到几百时：那时 softmax 就是一个
one-hot，梯度 `p - y` 在其余位置全部为 0。

## 常见坑

### 坑 1：`.contiguous()` 漏了

见上面第 5 步的注释。症状：`view size is not compatible with input
tensor's size and stride`。

### 坑 2：三个投影的 `view` 用了同一个 `n_head`

```python
q = self.c_q(x).view(B, T, self.n_head, self.head_dim)    # ✅
k = self.c_k(x).view(B, T, self.n_head, self.head_dim)    # ❌ 应该是 n_kv_head
```

无 GQA 时两者相等，所以**测不出来**。一旦开了 GQA（`n_kv_head < n_head`），
`c_k` 的输出维度是 `n_kv_head × head_dim`，用 `n_head` 去 view
会因为总元素数不匹配而报错 —— 至少这个错误是显式的。

### 坑 3：忘了 `use_rope` 的检查

```python
if self.use_rope and cos.size(1) >= T:      # ✅ 两个条件都要查
q, k = apply_rotary_emb(q, cos, sin), apply_rotary_emb(k, cos, sin)   # ❌ 无条件
```

这就是第 09 章那个「`--no-rope` 完全无效」的真实 bug。
写成无条件施加后，消融实验会得出「RoPE 毫无影响」的错误结论。

### 坑 4：`kv_cache.advance(T)` 放在循环里每层都调用

见代码注释里的 19 行说明。症状是生成胡言乱语但不报错。
第 34 章会详细讲。

## 延伸

**nanochat 的 fused QKVO**：nanochat 用一个 `(3D, D)` 的矩阵
同时算 q/k/v（把 3 拼在输出维），比本项目少三次小 GEMM 的 launch
开销。但它要求注意力权重布局是 `[n_head, 2, head_dim]` 这种特定排列，
而本项目要支持任意 `n_kv_head` 的 GQA，拆开更通用。

**Multi-Query Attention（MQA）**：`n_kv_head = 1`，所有 query 头共享
一组 kv。参数量和 KV cache 都能降到 GQA 的 1/n。是 GQA 的极端情况，
本项目已经支持（`n_kv_head` 可配），默认关闭。
