# 26 · 谨慎权重衰减

**「只在往 0 拉的时候才衰减」。** 听起来像废话，
但在 Muon 里这个符号判据能实实在在限制 WD 的伤害。

本章还有一个**意外的实测结论**：`full` 档真实配置下，
衰减项只有梯度项的 **2.1%** —— 也就是说谨慎 WD 在
本项目的主要档位上几乎无事可做。

---

## 本章目标

- 说清普通 WD 在 Muon 里为什么可能有害，以及「谨慎」怎么修
- 理解 mask 判定用的是**正交化之后**的量（这很容易误解）
- 验证一个关键等价性：`wd=0` 时谨慎版和普通版逐位相同

## 概念：普通 WD 在 Muon 里为什么可能有害

`muon_step` 的最后两行：

```python
if cfg.flavor != "simple" and cfg.use_cautious_wd:
    # ── 谨慎权重衰减 ──────────────────────────────────────
    # 普通 WD 惩罚所有参数，即使它这一步在往「正确方向」走。
    # 谨慎 WD 只在「梯度与参数同号」时衰减，也就是
    # 「这一步会把参数往 0 拉」的时候才衰减。听起来是废话，
    # 但在 Muon 里梯度方向是正交化过的，这个符号一致性
    # 判据能把 WD 的伤害限制住。
    mask = (g * stacked_param) >= 0
    stacked_param.sub_(lr * g + lr * hp["wd"] * stacked_param * mask)
else:
    stacked_param.sub_(lr * g + lr * hp["wd"] * stacked_param)
```

### ⚠⚠ `g` 是正交化之后的量

这是本章最容易误解的一点。

**`g` 在这里已经是 `Ortho(动量)`** —— 正交化会**完全重排元素的符号**。
所以 `g * W >= 0` 判定的是「**正交化后的更新量**是否和参数同号」，
**不是**「原始梯度是否指向 0」。

实测（用 `W = [2, 2, -2, -2]`、`g = [1, -1, 1, -1]`）：

```
  W    = [[2.0, 2.0, -2.0, -2.0]]
  g    = [[1.0, -1.0, 1.0, -1.0]]
  g*W  = [[2.0, -2.0, -2.0, 2.0]]
  mask = [[True, False, False, True]]
```

前两格 `W>0`：第 1 格 `g>0`（更新把 W 推得更远 → 衰减），
第 2 格 `g<0`（更新把 W 拉向 0 → 不衰减）。
后两格 `W<0` 同理。

**这个判据的真实含义**：「这一步的正交化更新，方向上是
把参数推得更远还是拉得更近」。

因为正交化重排了符号，这个判据和「梯度下降是否在减小
参数绝对值」没有直接关系 —— **它是一个关于更新量的判据**。

### 那为什么它有用

注释说「在 Muon 里梯度方向是正交化过的，这个符号一致性判据
能把 WD 的伤害限制住」。

**逻辑链**：

1. WD 的目的是**正则化** —— 让参数不要变得太大
2. 但如果这一步更新本身正在**增大**某个参数，
   那同时对它做衰减就是**对抗**（两个力互相抵消，净效果不可预测）
3. 谨慎 WD 的判据：**只在更新不会让参数绝对值变大时才衰减**

**这和「自适应梯度裁剪」是同一个思想** ——
不对抗正在做正确事情的量。

## 概念：实测谨慎 vs 普通

一步之后 `‖W‖_F` 的变化（`D=16` 随机矩阵，`lr=0.1`）：

```python
import sys, torch
sys.path.insert(0, "src")
from common.config import MuonConfig
from optim.muon import HyperParams, muon_step

D = 16
LR = 0.1


def step_once(W0, g0, cautious, wd):
    """★ 全部 clone —— muon_step 里的 .lerp_ 是 in-place，会改 g0。"""
    cfg = MuonConfig()
    cfg.flavor = "advanced"
    cfg.use_cautious_wd = cautious
    W = W0.clone()
    mom = torch.zeros_like(W)
    sec = torch.zeros(1, W.size(-2), 1)
    hp = HyperParams(step=0, lr=0, beta1=0, beta2=0, eps=0, wd=0, momentum=0.95)
    hp.set(lr=LR, momentum=0.95, wd=wd, beta2=0.9)
    muon_step(g0.clone(), W, mom, sec, hp, cfg)      # ★ 必须 clone
    return W


torch.manual_seed(7)
W0 = torch.randn(1, D, D)
g0 = torch.randn(1, D, D)
print(f"  初始 ||W||_F = {W0.norm().item():.6f}")
for wd in (0.0, 0.1, 0.5):
    a = step_once(W0, g0, False, wd)
    b = step_once(W0, g0, True, wd)
    print(f"  wd={wd:4.2f}  普通={a.norm().item():.6f}  "
          f"谨慎={b.norm().item():.6f}  "
          f"差={a.norm().item() - b.norm().item():+.6f}")
```

实测：

```
  初始 ||W||_F = 14.859324
  wd=0.00  普通=14.874376  谨慎=14.874376  差=+0.000000
  wd=0.10  普通=14.725839  谨慎=14.801471  差=-0.075632
  wd=0.50  普通=14.131695  谨慎=14.513795  差=-0.382100
```

**谨慎版的 `‖W‖` 明显更大 = 衰减更少。**

`wd=0.5` 时差 0.38（相对 2.7%）。`wd=0` 时完全一样。

> ⚠⚠ **我第一版这个实验写错了两次**，都值得记下来：
>
> **错误 1**：用 `g = [1,-1,...]` 手工构造「同号区/异号区」，
> 想验证逐元素的语义。但 `g` 会被正交化重排符号，
> **我构造的「同号/异号」分区在 mask 里根本不存在**。
> 测出来的 `‖W‖` 差异方向都是反的。
>
> **错误 2**：`step_once(W0, g0, ...)` 直接传 `g0`，
> 而 `muon_step` 里的 `g = stacked_grad.lerp_(momentum_buf, ...)`
> **是 in-place 的** —— 第一次调用就把 `g0` 改了，
> 第二次调用拿到的是被改过的梯度。
>
> 两个 bug 加在一起，让我一度以为 `wd=0` 时两种分支**不等价**，
> 进而以为第 28 章那个「去掉 `if wd != 0`」的修复不安全。
> **加 `clone()` 之后结论是：逐位相同，差异精确为 0。**

## 概念：★ 一个关键等价性（第 28 章的修复依据）

代码注释里说：

> 去掉是否安全？`wd == 0` 时 mask 那一项是 `0*param*mask == 0`，
> 数值上完全等价。

**这句话现在有实测支撑了**：

```
=== wd=0 时两种分支等价吗？===
  wd=0.00  逐位相同=True   最大差异=0.000e+00
  wd=0.10  逐位相同=False  最大差异=2.966e-02
  wd=0.50  逐位相同=False  最大差异=1.483e-01
```

**`wd=0` 时逐位相同、差异精确为 0。**

这不是废话 —— 它正是 `muon_step` 里**故意不判断
`hp["wd"] != 0`** 的安全依据。而那个「不判断」
省下了 **23% 的训练时间**（第 28 章完整讲这个 bug）。

```bash
uv run pytest tests/test_optim.py -k cautious -v
```

**如果 `wd=0` 时两种分支不等价**，那第 28 章的修复就是错的 ——
它会用「数值不完全等价」换 23% 的速度。
**所以这条等价性是第 28 章的地基，必须有判据。**

## 概念：★ 真实配置下衰减项只有 2.1%

一个必须说的实测。一步里两项的相对幅度：

```
  |O|max                    = 0.692164
  mask 为 True 的比例       = 49.6%
  梯度项最大幅度 lr*|O|max  = 0.069216
  衰减项最大幅度            = 0.151030
  -> 衰减/梯度 = 2.18   （这是 wd=0.5 的人造配置）
```

而 `full` 档的真实值：

| 量 | 值 |
|---|---|
| `MuonConfig.lr` | 0.02 |
| `MuonConfig.weight_decay`（λ_ref） | 0.1 |
| 缩放后实际峰值 λ | **0.02134** |
| 衰减/梯度 = `lr·λ / (lr·|O|max)` | **0.0213 / 0.69 = 0.031** |

（`|O|max ≈ 0.69`，见上面实测。）

**所以真实配置下衰减项的最大幅度只有梯度项的约 3%。**

**这意味着什么**：

1. **WD 在 `full` 档上基本不做事。** 它不是「精心调出来的正则化
   强度」，而是「小到几乎不起作用的量」。
2. **谨慎 vs 普通 WD 的差异也会被这个比例缩放** ——
   就算全部改成谨慎，最多也就是把 3% 的衰减去掉一部分。
3. **λ_ref = 0.1 是个推测值**（`MuonConfig` 的注释里明确说了
   「⚠ 0.1 这个值是**推测**，不是从 nanochat 抄来的」），
   而实测显示这个值小到几乎无效果。
   **所以「0.1 是不是选错了」这个问题，答案可能是「无所谓」。**

> ⚠ 这三点都是**基于幅度分析**的推断，不是实测 bpb。
> 要真知道谨慎 WD 有没有用，必须跑消融 —— 而 `full` 档一次 41 小时。
> `ablation` 档的 `weight_decay = 0.0`（缩放后峰值不同），
> 所以在 `ablation` 档上测这个也不对等。

## 手抄代码

```python
if cfg.flavor != "simple" and cfg.use_cautious_wd:
    # ── 谨慎权重衰减 ──────────────────────────────────────
    mask = (g * stacked_param) >= 0
    stacked_param.sub_(lr * g + lr * hp["wd"] * stacked_param * mask)
else:
    stacked_param.sub_(lr * g + lr * hp["wd"] * stacked_param)
```

**三处容易写错**：

**① `>= 0` 不是 `> 0`**

`g * W == 0` 的格子（梯度恰好为 0，或参数恰好为 0）
在 `>= 0` 下**会衰减**。用 `> 0` 的话这些格子不衰减。

哪个对？`g * W == 0` 意味着更新量为 0，
衰减它没有任何正则意义但会改变参数。**两种都讲得通**，
但 `>= 0` 是「除非确定是往 0 拉，否则衰减」的保守侧。

实测区分不出来（连续随机数据几乎不会正好为 0）。

**② `stacked_param` 是被原地修改的**

```python
stacked_param.sub_(lr * g + lr * hp["wd"] * stacked_param * mask)
```

**右侧的 `stacked_param` 是修改前的值**（PyTorch 先算完整个右侧表达式
再执行 `sub_`）。所以 `lr*wd*W*mask` 用的是旧参数 —— 正确。

如果你写成两行：

```python
stacked_param.sub_(lr * wd * stacked_param * mask)   # ★ 先衰减
stacked_param.sub_(lr * g)                          # ★ 再更新
```

**结果一样**（都是加法），但**浮点累加顺序不同**，
结果会有 1e-7 量级的差异。在 `torch.compile` 下可能被重排成不同顺序。
**保持单行更安全。**

**③ `cfg.flavor != "simple" and cfg.use_cautious_wd` 的短路顺序**

**`flavor` 检查必须在前面。** 因为 `flavor="simple"` 时
`MuonConfig` 里那些 `use_*` 字段虽然存在，但语义上不适用。

更重要的是：`and` 短路保证了 `flavor="simple"` 时
**连 `mask` 都不算** —— 少一次逐元素乘法和比较。

## 常见坑

### 坑 1：以为 `g` 是原始梯度

见上面。**这是本章最大的误解来源。**

### 坑 2：`step_once` 里忘了 `clone()`

见上面。`muon_step` 会原地改 `stacked_grad`：

```python
g = stacked_grad.lerp_(momentum_buf, hp["momentum"])
```

**`_` 后缀 = in-place。** 这也是为什么 `adamw_step` 里
写 `p32, g32 = p.float(), grad.float()` 而不是 `p.float_()` ——
AdamW 路径不能改 `grad`（它还要留给别的组用）。

⚠ 实际上 `adamw_step` 用的是非 in-place 的 `.float()`，
而 `muon_step` 用 in-place 的 `.lerp_()` ——
**因为 Muon 的 `stacked_grad` 是 `torch.stack` 出来的新张量**，
改它不影响原始的 `p.grad`。**这个区别是有意的。**

### 坑 3：以为谨慎 WD 能防住「对抗梯度」

它防的是「**更新量**和衰减对抗」。
但如果更新量本身因为正交化而指向错误方向，谨慎 WD 帮不上忙 ——
它只看符号一致性，不判断方向对错。

### 坑 4：以为 `wd` 默认 0.0 意味着「不用 WD」

在 `debug`/`smoke`/`ablation` 三个档位上确实是 0。
但 **`full` 档在 `PRESETS` 里显式给了 0.1**：

```
full      muon(lr=0.02 mom=0.95 ns=5 wd=0.1 flavor=advanced)
```

所以「默认 0」和「实际 0」是两件事。第 25 章验证 4 的分组表里
能看到 Muon 组的 `wd` 是 0.1。

## 延伸

**权重衰减的三种做法**

| 做法 | 公式 | 谁在用 |
|---|---|---|
| **L2 正则** | `g_total = g + λ·W` | 原始 Transformer |
| **解耦（AdamW）** | `W ← (1-lr·λ)·W`，然后 Adam | AdamW / 本项目 |
| **解耦 + 谨慎** | 只在 `g·W ≥ 0` 时乘 `(1-lr·λ)` | 本项目 advanced |

**为什么「解耦」是必要的** —— 第 21 章验证 3 实测过：
Adam+L2 的衰减强度随梯度尺度变化 45 倍，而 AdamW 完全不变。

**为什么还需要「谨慎」**

解耦解决了「衰减强度可控」，但没解决「**衰减和更新对抗**」。
谨慎版解决后者。

**LayerNorm + WD 的交互**

有个理论问题：**WD 会把参数拉向 0，而 LayerNorm 会除掉参数尺度**。
所以 WD 对有 norm 的层作用有限（scale 变了，norm 之后又归一化了）。

Muon 的更新后有 `c_proj`（第 14 章：输出投影），
而 `c_proj` 之后直接进残差。**残差流没有 norm**（norm 在 block 内部）。
所以 WD 对 `c_proj` 的作用是实在的。

**WD 与稀疏性**

有理论工作（*On the interplay between sparsity and
weight decay*）指出：WD 会**破坏稀疏性** ——
因为它给每个参数同样的相对衰减，等于让小权重更容易被清零
（相对衰减对小参数更致命）。

**MoE 模型里 WD 特别危险** —— 专家的采样率不均，
不受欢迎的专家的参数会被 WD 持续拉向 0，最终变成死专家。
`schedule-free`（第 22 章提到的）的动机之一就是这个。

**`wd` 和学习率必须一起扫**

因为每步衰减是 `lr·λ`（不是 `λ`）。
- `lr` 调大 → 衰减也变大
- `λ` 调大 → 衰减也变大

**解耦 WD 的一个好处就是：可以分别扫这两个而不互相干扰**
（这就是第 21 章那个 45 倍差异的意义）。
