## 概念：单卡下的「退化」

`compute_init` 返回五个值：

```python
def compute_init(device_type: str = "cuda"):
    """
    统一的初始化入口。返回 (ddp, rank, local_rank, world_size, device)。

    本项目只有 1 张卡，所以 ddp 恒为 False、world_size 恒为 1。
    但保留这套返回值的形状，是为了让你读 optim/muon.py 时，
    能看清「分布式分支在单卡下是怎么退化的」（教程卷6）。
    """
    torch.manual_seed(42)
    if device_type == "cuda":
        torch.cuda.manual_seed(42)
        torch.set_float32_matmul_precision("high")   # 允许 tf32

    device = torch.device(device_type if device_type != "cuda" else "cuda:0")
    return False, 0, 0, 1, device
```

**恒定返回 `(False, 0, 0, 1, device)`。**

而 `step()` 里的退化点在第 267-269 行：

```python
if dist.is_available() and dist.is_initialized():
    rank, world = dist.get_rank(), dist.get_world_size()
else:
    rank, world = 0, 1   # ← 单卡退化点：下面所有 world>1 的分支都不执行
```

**注意那行注释**：`# ← 单卡退化点`。

所以：

| 分支 | 单卡行为 |
|---|---|
| `if world == 1: ... continue` | **总是走这条** |
| `if p.numel() < 1024:` | 不执行 |
| `else: reduce_scatter ...` | 不执行 |

⚠ **但这些代码从未在多卡下运行过。** 它们是「照抄 / 推导」的形态，
**不是实测正确的形态**。

第 02 批交付时它们的判据是「代码在单卡下不崩」，
**不是「多卡下正确」**。

> **这是本章最该记住的一句**：
> **本项目的分布式分支是未验证代码。**
> 真要用多卡，先自己在小模型上验证。

## 概念：★ 为什么 Muon 难以用 FSDP

这是本章的核心，也是那个「只有读到代码才有答案」的问题。

### Muon 需要整个矩阵

第 22-23 章讲过：Muon 的更新是

```
O = Ortho(M)       ← 需要完整的 m×n 矩阵的谱
W ← W - η·√(m/n)·O
```

**正交化需要完整矩阵。**

FSDP（ZeRO-3）的做法是把参数按 `dim 0` 切到各卡，
每张卡只有 `1/world_size` 个行。
**「把完整的谱算出来」这件事做不到** —— 每张卡只有矩阵的一小块。

DDP 没有这个问题：每卡有**完整**的模型副本，
只同步梯度。

### 但 DDP 的问题是优化器状态

| | DDP | FSDP |
|---|---|---|
| 参数 | 每卡完整 | 分片 |
| 梯度 | all-reduce（求和） | reduce-scatter |
| **优化器状态** | **每卡完整（浪费）** | 分片（省） |

DDP 的浪费：模型大到装不下时，
DDP 也用不了（每卡要装完整模型 + 完整优化器状态）。

**AdamW 的状态是参数的两倍**（`exp_avg` + `exp_avg_sq`）。
所以 DDP 下每卡要装 3 份参数。

### ZeRO-2 的做法（本项目 AdamW 分支）

```python
if world == 1:
    self._fn_adamw(p, p.grad, st["exp_avg"], st["exp_avg_sq"], self._hp)
    continue

# ---- 分布式：ZeRO-2 风格（教程卷6 专章）----
if p.numel() < 1024:
    # 小参数（标量类）：all_reduce 梯度，状态保持复制
    dist.all_reduce(p.grad, op=dist.ReduceOp.AVG)
    self._fn_adamw(p, p.grad, st["exp_avg"], st["exp_avg_sq"], self._hp)
else:
    # 大参数：reduce_scatter -> 各 rank 只更新自己那一片
    #        -> all_gather 拼回完整参数
    # 净效果：优化器状态天然按 world_size 分片
    assert p.shape[0] % world == 0, (
        f"reduce_scatter 要求 shape[0]={p.shape[0]} "
        f"能被 world_size={world} 整除")
    rs = p.shape[0] // world
    grad_slice = torch.empty_like(p[:rs])
    dist.reduce_scatter_tensor(grad_slice, p.grad, op=dist.ReduceOp.AVG)
    lo, hi = rank * rs, (rank + 1) * rs
    self._fn_adamw(p[lo:hi], grad_slice,
                   st["exp_avg"][lo:hi], st["exp_avg_sq"][lo:hi],
                   self._hp)
    gathered = torch.empty_like(p)
    dist.all_gather_into_tensor(gathered, p[lo:hi])
    p.copy_(gathered)
```

**这是 ZeRO-2 的核心三步**：

```
1. reduce_scatter：梯度求和并按 rank 切分 -> 每卡拿到 1/world 的梯度
2. 本地更新：只用自己那一片梯度和状态更新参数
3. all_gather：把更新后的参数拼回完整矩阵
```

**净效果**：优化器状态天然按 `world_size` 分片，
但参数在每次 step 后是完整的。

### 两个关键约束

**① `p.shape[0] % world == 0`**

```python
assert p.shape[0] % world == 0, (
    f"reduce_scatter 要求 shape[0]={p.shape[0]} 能被 world_size={world} 整除")
```

**按第 0 维切分**。所以 `lm_head.weight` 是 `(768, 16384)`，
`shape[0] = 768`。`world_size=8` → 768/8 = 96 ✓
但 `world_size=7` → 768 % 7 = 5 ✗ **断言会炸。**

⚠ **这意味着某些卡数根本不能用。** 不是所有 `world_size` 都可行。

**② `p.numel() < 1024` 的分界**

小参数（`resid_lambdas` 24 个、`smear_lambda` 1 个）**不分片**，
用 all_reduce 同步梯度、状态保持复制。

**为什么？** 因为分片的开销（两次通信 + 切分）比参数本身还大。
一个 24 元素的参数，切成 8 份是每卡 3 个 ——
省不到任何东西，还多两次通信。

**1024 这个阈值是硬编码的** —— 和第 30 章的 `400` 一样的魔数。

### Muon 分支没有对应的实现

看 `kind == "muon"` 分支（`muon_step`）：

```python
elif kind == "muon":
    params = group["params"]
    st = self._init_muon_state(params)
    stacked_grad = torch.stack([p.grad for p in params])
    stacked_param = torch.stack(params)
    m, n = params[0].shape[-2], params[0].shape[-1]
    ...
    self._fn_muon(...)
    torch._foreach_copy_(params, list(stacked_param.unbind(0)))
```

**没有任何 `dist` 调用。**

因为 Muon 需要完整矩阵（见上面），ZeRO-2 的分片对它无效。

**所以这个分支在 `world > 1` 下的正确行为是：仍然每卡处理完整矩阵
（等价于 DDP + 状态复制）。** 但代码没有明确写这一点 ——
它只是「不调用 dist」，而 `stacked_grad` 是本地的 `p.grad`（未同步）。

⚠ **未同步的梯度意味着 DDP 语义下所有卡看到不同的梯度 ——
这会让所有卡朝不同方向走，从而发散。**

**所以 `world > 1` 时这个分支是错的。**
「没有 dist 调用」不等于「正确」。

### nanochat 的答案：Muon 只在通信稀疏时同步

Karpathy 的 nanochat 用的是一个更特殊的设计：
**在单次 GPU 组内用 DDP，跨节点用梯度累积**，
而不是把模型切到多卡。

这样每张卡都有完整模型（DDP 语义正确），
只是「一个大 batch 被切成若干小 batch 顺序处理」。

**代价**：没有模型并行，单卡显存仍要装下整个模型。

## 常见坑

### 坑 1：以为分布式分支是验证过的

**没有。** 判据只保证「单卡下不崩」。

### 坑 2：以为「没有 dist 调用」= 正确

Muon 分支就是例子（梯度未同步 = DDP 下发散）。

### 坑 3：随便选 `world_size`

`assert p.shape[0] % world == 0` 只作用在 **AdamW 大组**上，
而它们的 `shape[0]` 都是 16384（2 的幂）——
所以**只支持 2 的幂次卡数**，`world_size=3/5/7` 会直接炸。

⚠ 而 `(1,24)` 的 `smear_gate` 碰不到这个断言（它在 Muon 组）——
**这是运气，不是设计**。改了分组规则就会暴露。

### 坑 4：以为 ZeRO-2 适合 Muon

**不适合。** Muon 需要完整矩阵。

### 坑 5：忘了 `torch.distributed` 从没被初始化

```python
if dist.is_available() and dist.is_initialized():
```

**本项目从不调用 `init_process_group`。**
所以 `dist.is_initialized()` 恒为 False，
`world` 恒为 1。

**整个分布式代码路径是「语法正确但从未执行」的。**

## 延伸

**DDP / FSDP / ZeRO 的区别**

| | 参数 | 梯度 | 优化器状态 | 通信 |
|---|---|---|---|---|
| **DDP** | 复制 | all-reduce | **复制** | 每步 1 次全量 |
| **ZeRO-1** | 复制 | all-reduce | 分片 | 1 次 + 状态 |
| **ZeRO-2** | 复制 | reduce-scatter | 分片 | 1 次（省显存） |
| **ZeRO-3** | **分片** | all-gather | 分片 | 每层前后各 1 次 |

本项目的 AdamW 分支是 **ZeRO-2**（参数复制、状态分片）。

**Muon 和 ZeRO-3 的根本冲突**

ZeRO-3 在 forward 之前 all-gather 参数，
算完立刻 reshard。**每层的前向反向都要通信两次。**

而且 Muon 需要在 optimizer step 时看到完整矩阵 ——
那时参数已经被 reshard 回各卡了。**需要额外 gather 再 scatter。**

**实际方案（Kimi / GLM 用的）**

**DiLoCo**（DeepMind 2024）：
- 单个「副本组」内用 DDP
- 跨副本组**只在周期性同步时**做真正的 Muon 更新
- 同步之间用普通 SGD + 自适应近似

这让 Muon 能在节点间跑。**本项目没实现**。

**`torch.distributed` 的两种后端**

- **NCCL**：GPU 之间，走 NVLink/PCIe
- **Gloo**：CPU 之间

本项目连 `init_process_group` 都没调，所以后端也没选。

**为什么保留这些分支而不是删掉**

**教学价值**。删掉的话，「为什么 Muon 不适合标准分布式」这个问题
就没有答案 —— 而它是理解 Muon 局限性的关键。

第 33 章（推理）会讲另一个「保留但用不上」的案例：
`KVCache` 在训练时完全用不到，但必须存在。
